## Version and file conventions

- Baseline: `model/223C_Existing_Shell_v02.blend`; keep v01 and v02 intact.
- Blender units: metres internally, millimetres displayed.
- Loose furniture collection in current source: `13 | Loose furniture — empty for next iteration`; inspect the saved file before use.
- Useful existing cameras: `CAM 02 | Top plan — dimensions in model` and `CAM 05 | Living eye level`. Adapt framing for living-room comparisons, then keep it consistent.
- Baseline rebuild scripts overwrite v02/previews. Do not run them to create furniture variants.
- Create variant folders only as used: `design/living-room/iterations/01-layout-a/`, with a `.blend` or reproducible scene parameters, top/eye-level previews and `REVIEW.md`.
- `REVIEW.md` records option ID, parent version, hypothesis, changed variables, dimensions, checks and unresolved facts, cost status, feedback and decision.
- Update this plan's current stage and the brief after meaningful decisions. Keep rejected options and the reason for rejection.

## Comparison rubric

| Gate / priority | Evidence needed |
| --- | --- |
| Existing architecture and agreed scope | Compare with baseline and recorded permissions |
| Required capacity and retained pieces | Counts, dimensions and actual seating/use assumptions |
| Routes and opening access | Measured gaps and operating envelopes, including adjacent circulation |
| Cost transparency | SGD, furniture scope, sourced costs or separated allowances; no numerical cap set |
| Primary activities and comfort | Household routine and seat-by-seat use scenario |
| Appearance and maintenance | Owner's reference features, reactions and upkeep tolerance |

The first four rows are provisional feasibility gates, to be adjusted when the brief is known. Rank the preference criteria with the owner; do not invent weights or use scores to hide a failed constraint.
